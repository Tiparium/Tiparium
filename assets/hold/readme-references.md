## Individual References

### Karan Chandekar

- https://github.com/KaranChandekar
- Useful qualities:
  - General structure works well.
  - Clear sectioning.
  - Brief opening blurb.
  - Includes about/projects/tech stack style sections.
- Avoid:
  - Visually noisy presentation.
  - Emoji used as visual punctuation.
  - Decorative or nonfunctional elements.
  - Buttons or images that imply functionality but only link to static button images.
- Takeaway:
  - Use the structural density as a reference, but make every visual and link earn its place.

### Blackjacx

- https://github.com/blackjacx
- Useful qualities:
  - Very simple.
  - Bite-sized introduction.
  - Low-maintenance presentation.
- Constraints for this project:
  - Social links should be limited to real professional surfaces, likely GitHub and LinkedIn.
  - Avoid adding empty or placeholder social presence just because many templates include it.
- Takeaway:
  - Good lower bound for simplicity: concise, professional, and not overbuilt.

## Emerging Direction

- Prefer utilitarian, professional presentation over decorative profile-readme tropes.
- Avoid needless GIFs, flashing visuals, decorative badges, and clutter.
- Use visuals only when they communicate meaningful information about the person, project, product, architecture, or workflow.
- Avoid emojis except where there is a specific reason for one to exist.
- Do not include dead links, placeholder buttons, fake demos, or ornamental UI.
- Curate selected work rather than expose every public repository.

  - Particularity
  - Harbormaster
